# 幹部会用「受注の現状」資料の作り方

幹部会のたびに、前回の幹部会資料（＝前回のリスト）と業務進捗シートの今の状態を比べ、変わったところが一目でわかる Word 資料を作る。
見本は `reports/2026-10-25/受注の現状_20261025.docx`（2026/10/26 幹部会用・承認済みのまとめ方）。

## 使うもの

- 業務進捗シート（Google スプレッドシート）: `1delYDMRY96Q0qLr77aZPAF59y6pU1RnHNkDClchYX-I`（2026.02~ 業務進捗シート）
  - 担当者シート: 長友・川瀬・櫻井・林・山田・井口（各シート上が【受注案件】、下が【見込み案件】）
  - 「2026売上合計」: 完工・請求が済んで売上計上された案件の移動先
  - 「2026年失注案件」: 失注案件の移動先。T列が「失注理由」
- 前回の資料データ: `reports/<前回の日付>/data.json`（いちばん新しいフォルダ）
- Google カレンダー: 予定名「幹部会」。前回＝直近の過去の幹部会、今回＝次の幹部会
- ツール（このフォルダ内）
  - `build_report.py data.json template.docx 出力.docx` … data.json から資料を作る
  - `extract.py 資料.docx data.json` … できあがった資料（人が手直しした版も）から data.json を取り出す
  - `template.docx` … 用紙設定（A4横）のひな形

## 対象と区分

- 対象は **100万円以上（税抜）** の案件。担当は長友・川瀬・櫻井・林・山田・井口。
- 金額の区分は **500万円以上（大型）** と **100～499万円（中型）**。
- 1ページ目＝受注済み案件、2ページ目＝未受注（見込み）案件。

### 1ページ目：受注済み
1. 【受注済み／大型（500万円以上）】
2. 【受注済み／中型（100～499万円）】
3. ◆その他（要確認）

### 2ページ目：未受注（見込み）
1. 【未受注（見込み）／大型（500万円以上）】
2. 【未受注（見込み）／中型（100～499万円）】
3. 【前回時点で金額未定だった見込み】（該当があれば）
4. 【前回以降の新規見込み（100万円以上）】（前回の幹部会の翌日以降に登録された案件）

## 作り方のルール

1. **前回のリストをそのまま転記する**（行の並びも前回どおり）。前回の data.json の行を土台にし、今のシートの状態と比べる。
   - 前回「完工・請求」「失注」で色付けした行は、今回のリストからは外す（もう比べる必要がないため）。
   - 金額が100万円未満になった・区分が変わった案件は、変更欄にその旨を書く。
2. 列は「物件所在／名前／担当／工事内容／金額（税抜）／○/○時点の変更」。**変更欄で何が変わったかが分かるように**書く（例: 「完工・請求（売上合計へ移動）」「受注日9/5を記入」「金額変更」）。
3. **色の付け方**
   - **赤字**＝前回から変わった金額・内容（変わったセルだけ）。変わっていないところは黒字のまま。
   - **行全体を塗りつぶす**: 緑＝完工・請求、黄＝見込み→受注、灰＝失注、青＝前回以降の新規見込み。塗りつぶした行は変更欄を太字。
   - 取消線＝前回時点ですでに完了・失注扱いだったもの。
   - 各ページの上に **色の説明** を入れる（build_report.py が自動で入れる）。
4. **失注案件は、変更欄に理由も書く**。「2026年失注案件」シートの「失注理由」列から取る。例: 「失注（理由：娘さんの同意が得られず）」。理由欄が空なら「失注（理由：シート未記入）」と書き、その他（要確認）にも入れる。
5. **完工・請求の判断**: 「2026売上合計」へ移動した、または請求日が入った案件。工期が過ぎても完工日・請求日が空欄の案件は、その他（要確認）に書く。
6. **金額未定・はっきりしないものは「その他（要確認）」にまとめる**（文章で1行ずつ）。例: 完工日・請求日が未記入の案件、金額未定の案件（新規分は【新規】と付ける）、シート間で食い違う案件。表と重複する内容は書かない。
7. 文字は少なく、シンプルに。2ページに収める（2ページ目の行が多いときは build_report.py が文字を小さくして行の高さを詰める）。

## 手順

1. カレンダーで前回と今回の幹部会の日付を確認する。
2. `reports/` のいちばん新しい `data.json`（前回分）を読む。
3. 業務進捗シート（6人の担当シート・2026売上合計・2026年失注案件）を読み、ルールどおりに今回の data.json を作る。
   - `date`（例 "2026年11月12日"）、`prev`（前回の比較日 例 "10/25"）、`new_since`（前回の翌日 例 "10/26"）を入れる。
   - 各行の `色`（完工／受注／失注／新規／空）、`赤字`（赤字にする列名のリスト）、`取消線` を付ける。
4. `python3 .claude/skills/kanbukai-report/build_report.py data.json .claude/skills/kanbukai-report/template.docx 受注の現状_YYYYMMDD.docx` で資料を作り、PDF にして見た目を確認する（2ページに収まっているか、文字が切れていないか）。
5. `reports/YYYY-MM-DD/` に docx と data.json を保存して、コミットして push する（次回の比較元になる）。
6. 資料を Google ドライブにもアップロードし（Word のまま。Google ドキュメントに変換しない）、リンクを利用者に知らせる。
7. 人が資料を手直ししたら、その docx を `extract.py` で data.json に戻して `reports/` を更新する（次回はその版と比べる）。
8. 次の幹部会の前日の自動実行がまだ登録されていなければ登録する。

シートの中身は変更しない（読むだけ）。
